## Observations

- **Tool-only findings (F08, F10):** neither Bandit nor Semgrep alone found F02/F03/F04/F06/F11, and neither A, B, nor C reported F08 (plaintext/hardcoded user credentials) or F10 (bind-to-all-interfaces). These were visible only to the SAST tools, showing the LLM reviews and the SAST scan are complementary, not redundant.
- **Context/requirements changed what was found, not just how it was described:**
  - A (no context) and B (context, no requirements) both collapse authentication and authorization into one finding per endpoint (A: VULN-02/VULN-03; B: V2/V3) and miss the download endpoint's missing-auth issue (F02), the input-validation gaps (F06), and the error-handler disclosure (F11) entirely.
  - C (full R1–R7) is the only response to surface F02, F06, and F11 — directly traceable to R1/R6, R5, and R7 being stated explicitly in its prompt.
  - Conversely, C is the only response that **dropped** the configuration findings F07 (hardcoded secret key) and F09 (debug mode) that both A and B caught — likely because C's review was anchored to the given requirements table (which says nothing about secrets or debug flags) rather than a general code audit.
- **No response found an issue the tools and code do not support** — i.e., no false positives among A/B/C findings cross-checked here; all mapped findings are Confirmed against the source.
